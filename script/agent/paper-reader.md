# 论文阅读技能 (Paper Reader)

## 用法

- `/paper-reader [arXiv URL或ID]` — 下载论文并生成分析报告
- `/paper-reader [本地PDF/tex路径]` — 直接分析本地论文
- `/paper-reader [raw_data/仓库路径]` — 从已 clone 的代码仓库读取（自动补下载论文）

示例：
- `/paper-reader https://arxiv.org/abs/2603.19312`
- `/paper-reader raw_data/le-wm`

## 与 deep_read.md 的关系

本技能 = **[deep_read.md](deep_read.md) 审稿思辨骨架** + **实践可读层**（核心五问、shape/超参、框图、带数字实验）。

| 层次 | 来源 | 产出 |
|------|------|------|
| **思想层** | deep_read.md：主张拆解、共识/反对、假设边界、实验审计、批判性质疑 | 读懂「为什么做、是否成立、争议在哪」 |
| **实践层** | pi0_5/nwm 金标准 + graph-viz | 读懂「数据怎么流、模块多大、数字多少」 |

**不是**纯 Distill 说明书，**也不是**纯 rebuttal；两者同一份报告、同一套章节。

## 北极星

**读完 `分析报告` + `inference/training` 框图，即可理解该开源工作 80%~90%**——包括方法机理、实验结论、学术定位与主要质疑点，无需再开原论文。

### 与 graph-viz 分工

| 技能 | 职责 |
|------|------|
| [graph-viz.md](graph-viz.md) | 30 秒看清数据流、shape、训练/推理差异 |
| paper-reader | 思辨 + 实践：**主张→方法→证据→定位→质疑→边界** |

## 读者画像

- 熟悉深度学习 **forward/back**，未在某个仓库上完整闭环过
- 需要：**先抽象故事线，再落到规格细节**；同时需要 **适度的批判性讨论**，而非只看「怎么做」
- 写作角色：**偏理论+工程的审稿人**，产出兼顾可读的技术报告

## 输入

1. **arXiv URL 或 ID** / **本地 PDF/tex** / **`raw_data/{repo}/`**
2. 可选：`CATEGORY`、`alias`、`BASE_DIR`

### 路径约定

| 概念 | 示例 |
|------|------|
| 仓库 | `raw_data/le-wm/` |
| 分析 | `analysis/wam/lewm/` |
| 论文 | `raw_data/le-wm/paper/` |
| 框图 | `lewm_inference.png`, `lewm_training.png` |

## 核心规范（5 条硬约束）

| # | 约束 | 说明 |
|---|------|------|
| 1 | **自足性** | 正文禁止「详见论文 Sec X」「见 `foo.py`」；差异写入 §2.7 对齐表 |
| 2 | **思辨+实践并重** | 每篇报告必须同时含：**Claims 表**、**谱系/共识讨论**、**§5 质疑**；不能只写 pipeline |
| 3 | **规格落地** | shape/dtype/归一化、架构参数表、默认超参 |
| 4 | **实验带数+审计** | 具体数字 + 类型标注；§3.3 审计 baseline 公平性与盲点 |
| 5 | **框图联动** | 有代码则 graph-viz **双图**；§2.3 节点名与框图一致 |

### 写作决策（已确认）

| 项 | 规则 |
|----|------|
| 公式 | **直觉层**：主 loss + 推理/规划式；关键假设与符号 inline；不求长推导 |
| 代码 | **主路径**：train/infer + 默认 config → §2.7 |
| 框图 | 有代码 → 强制 inference + training |
| 本机实测 | 不纳入标准模板 |

### 强制行为规范（同 deep_read.md）

- 严禁猜测作者未表达的意图；严禁杜撰引文或数字
- 论述可追溯至原文（Section/Figure/Table）或真实文献
- 未检索到反对/支持证据时，写明「当前未检索到明确证据」
- 遇不透明信息标注："文档未披露 / 技术细节缺失"

## 执行流程

| 阶段 | 做什么 | 产出 |
|------|--------|------|
| 1 获取 | arXiv / `raw_data/{repo}` 补 paper | `paper/` |
| 2 读+对齐 | 论文 + 主路径代码（train/infer + config） | 笔记 |
| 3 框图 | graph-viz 双图 | PNG/PDF |
| 4 写报告 | 按 §0~§5 填模板 | `{alias}_{id}_分析.md` |

### 获取论文

```bash
bash ~/.claude/skills/paper-reader/scripts/download_arxiv.sh <ARXIV_ID> <BASE_DIR>/raw_data/<REPO>/paper
```

**仓库模式**：`paper/` 为空时从 README 提取 arXiv ID 并下载；`alias` 可与 repo 名不同（`le-wm` → `lewm`）。

**无开源代码**：跳过框图；§2 以论文机理表替代。

## 报告模板

路径：`analysis/{category}/{alias}/{alias}_{ARXIV_ID}_分析.md`  
篇幅：**250~400 行**（思辨节精简写，不灌水）

## §1 主张、动机与学术定位（思想层 · 对应 prompt §一、§四）

### 1.2 核心主张（Claims）

|---|------|----------------|---------|---------|

### 1.3 创新边界
- 机制变革 vs 成熟方法重组/调参；逐项说明

### 1.4 研究目标与子问题
- 核心问题、实际意义

### 1.5 数据从哪来 / 长什么样

### 1.6 怎么评测 / 验证什么

### 1.7 方法谱系与学术定位
**问题共识度**：共识 / 有争议 / 作者自创

| 方法 | 范式 | 与本文关系 | 一句差异 |
|------|------|-----------|---------|

- **主流延伸**：与哪些工作一致、共识点在哪
- **竞争/反对观点**：争议技术点；本文是否回应（无证据则声明未检索到）
- **范式定位**：改进 / 挑战 / 并行替代

## §3 实验与证据审计（思想+实践 · 对应 prompt §三）

{白话：实验能否支撑 §1.2 的 Claims}

### 3.3 实验审计
- **Claim 覆盖**：每条主张是否有对应实验；缺什么
- **Baseline 公平性**：是否真 SOTA；算力/调参是否一致
- **盲点**：作者回避的敏感变量或边界场景

### 3.4 弱点与局限
